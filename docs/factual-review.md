# Factual review and unresolved holds

The writing model and a critic can both make mistakes. If a critic rejects an exact supplied source sentence, or approves that sentence using unrelated claim IDs, the harness preserves the disagreement before automatic rewriting. It keeps the original text, source claims, review, task identity and contextual evidence in a hash-bound receipt under `state/review-disputes/<package-id>/`.

A dispute is neither a factual approval nor a confirmed writing defect. Exact copying alone cannot prove that surrounding qualifications, dates or antecedents were preserved. Paraphrases remain subject to the normal factual checks. Unsupported review rows may have no citation IDs; supported rows require evidence.

The same newsletter or script stage cannot be rerun while its immutable dispute receipt remains unresolved. This prevents repeated writing costs from the same inconsistent review. It does not block unrelated visual development. Automatic adjudication and a verified clearance workflow are not yet implemented. Preserve the receipt and source package for independent review; deleting it is not evidence of resolution.

## Local reviewer calibration

Run `node --import tsx ops/qualify-general-critic.mts --describe` to inspect the controls without calling a model. The developer execution helper requires an explicit plan naming the active workspace, a measured installed model identity, current memory fit and an original parent allowance. Start the worker with the correct `HARNESS_WORKSPACE` before importing its model transport.

The four controls cover exact-source claims with reordered IDs, faithful paraphrases, inventions, qualifiers, plans, dates and source silence. They stop on the first failure, use at most four physical calls and do not enable hosted rescue. Passing this suite covers only the current four-sentence/four-claim general-review contract. It does not qualify specialist review, longer packets, source retrieval, full writing, narration or publishing. The helper preserves actual runtime identity and schema receipts; OpenCode remains the runner, not the model.

Choose an installed model in the Journey model advisor, check its exact context and memory estimate, then establish quality for each intended role. Models missing a reliable memory estimate remain unqualified. Compatible transport and passing software fixtures do not establish reliable writing. No model has universal reliability, and this build does not promise that every local model can complete the workflow.
